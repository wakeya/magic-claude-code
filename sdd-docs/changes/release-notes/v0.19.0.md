## v0.19.0 更新内容

### Added
- **AI 自动生成自定义额度脚本**（#37）：在供应商额度配置中输入目标 URL、DevTools 请求信息和响应样例，即可生成兼容 `({request, extractor})` 合同的 JavaScript。生成器复用现有 Provider 的 LLM 凭据，支持 Anthropic、OpenAI Chat Completions 和 OpenAI Responses 协议，并可选择具体模型。
- **脚本样例、自检与多轮修正**（#37）：生成窗口提供常见脚本样例；生成后会检查 Cookie/Authorization/sec_token 遗漏、空 POST body、占位符错位、硬编码 URL 和响应解析等常见问题，并自动把自检结果交给 AI 继续修正。后端错误详情会显示在前端，便于定位供应商特有问题。
- **form body 与附加密钥**（#37）：自定义脚本新增 `BodyType: "form"`，使用 `application/x-www-form-urlencoded` 编码，嵌套对象自动序列化为 JSON；`{{apiKey}}`、`{{apiKey2}}` 等占位符可用于 JSON/form body 的字符串值。新增第二密钥槽，保存、测试、保留、替换和清除语义与原脚本密钥一致，API 不返回密钥明文。

### Changed
- **JavaScript 改由隔离 worker 执行**（#42）：request 解析和 extractor 各自在独立、短生命周期的 `mcc __script-worker` 子进程中执行。父服务不再直接运行 goja；HTTP 请求、密钥替换、SSRF/同源校验、错误脱敏和额度结果标准化仍由父进程负责。现有脚本、配置 JSON 和管理 API 无需迁移。
- **平台资源边界**（#42）：Linux 4.7+ 使用 `RLIMIT_DATA`，Windows 使用 Job Object 限制 worker 进程内存；生产 worker 硬上限为 512 MiB、Go 软上限为 384 MiB。macOS 暂无经实机验证的 Go mmap 硬内存机制，因此自定义额度脚本会 fail closed，不在无隔离边界时执行。

### Fixed
- **同源 307/308 重定向不再丢失 POST body**（#40）：重定向后的请求会重新发送已编码 body，并恢复脚本 headers 与 form `Content-Type`。
- **千问 Token Plan 利用率换算**（#37）：`per5HourPercentage`、`per1WeekPercentage` 等字段按 `0..1` 的已用比例乘以 100，修正已用/剩余语义误判。
- **提高 AI 输出兼容性**（#37）：允许模型在脚本外附带解释文字；系统提示明确 extractor 收到的是已经解析的 JSON 对象，不应再次 `JSON.parse`，并强化 Percentage 字段和 DevTools 请求信息的生成规则。
- **前端更新后自动加载新资源**（#37）：入口 HTML 使用 `no-cache`，内容 hash assets 使用 immutable 长缓存，避免 Docker 重建后浏览器继续引用旧 bundle。
- **兼容 Claude Code 2.1.220 新探针**（#42）：`GET/HEAD /api/hello` 返回本地成功响应；`GET /v1/environment_providers` 返回 `{"environments":[]}`，消除连通性检查和云环境列表的 404/异常噪音。相关写端点仍不开放。

### Security
- **OOM 与崩溃隔离**（#40、#42）：正则预检继续快速拒绝常见超大 Array、无限循环和超长字符串；动态表达式即使绕过预检，也只能耗尽或终止受限 worker，不会与 MCC 父服务共享 Go 堆。
- **有界且 fail-closed 的 worker 协议**（#42）：stdin 使用有长度限制的帧化协议，stdout/stderr 分别限制为 4 MiB/64 KiB；worker 资源限制初始化失败、协议畸形、输出超限、超时或 context 取消时均拒绝执行或终止子进程。worker stderr 和协议错误不会进入管理 API 响应。
- **配置密钥保持在父进程**（#42）：worker 收到的是仍含 `{{apiKey}}` 等占位符的原始脚本，不接收实际 placeholder values；extractor worker 仅额外接收有界的上游响应体。配置密钥只在父进程的 Go 请求配置中替换，不进入 goja runtime。若管理员把秘密硬编码进脚本文本，该文本仍会进入 worker，因此仍应使用占位符。
- **LLM endpoint SSRF 纵深防御**（#37、#42）：目标 host 在配置预检和实际拨号时都会检查，阻断内置云元数据 IP 并防止 DNS rebinding；LLM HTTP 客户端禁用重定向。管理员仍可连接可信的 loopback/私网 LLM 代理。
- **PostCSS source map 路径遍历修复**：前端 lockfile 将 PostCSS `8.5.16` 升级到 `8.5.25`，修复 GHSA-r28c-9q8g-f849（恶意 `sourceMappingURL` 可导致任意 `.map` 文件泄露）。`npm audit` 现为 0 vulnerabilities。

### 升级说明
- 本版本不修改自定义脚本合同和持久化格式；已有脚本在受支持的 Linux/Windows 环境中可直接继续使用，macOS 限制见上文。
- Linux 部署请使用 4.7 或更新内核，并确保容器/宿主机 `ulimit -d` 不低于 512 MiB，否则 worker 可能因有效上限被下调而无法处理接近 2 MiB 的响应。
- AI 生成的脚本在保存前仍应由管理员检查请求 URL、headers、Cookie/Token 占位符及 extractor 的已用/剩余语义。

## v0.19.0 Release Notes

### Added
- **AI-generated custom quota scripts** (#37): Enter a target URL, DevTools request details, and a response sample in the provider quota settings to generate JavaScript compatible with the `({request, extractor})` contract. The generator reuses an existing Provider's LLM credentials, supports Anthropic, OpenAI Chat Completions, and OpenAI Responses protocols, and lets you choose the model.
- **Script examples, auditing, and multi-round repair** (#37): The generator includes common examples, checks generated scripts for missing Cookie/Authorization/sec_token values, empty POST bodies, swapped placeholders, hard-coded URLs, and response-parsing mistakes, and automatically feeds audit findings back to the AI for another repair round. Backend error details are now surfaced in the UI for provider-specific diagnosis.
- **Form bodies and an additional secret** (#37): Custom scripts now support `BodyType: "form"` with `application/x-www-form-urlencoded` encoding; nested objects are JSON-serialized. Placeholders such as `{{apiKey}}` and `{{apiKey2}}` can be used in string values inside JSON or form bodies. A second secret slot follows the original script key's save, test, preserve, replace, and clear semantics, while APIs never return plaintext secrets.

### Changed
- **JavaScript now runs in isolated workers** (#42): Request parsing and extractor execution each run in a separate, short-lived `mcc __script-worker` subprocess. The parent service no longer executes goja directly; HTTP requests, secret substitution, SSRF/same-origin checks, error redaction, and quota-result normalization remain in the parent. Existing scripts, configuration JSON, and admin APIs require no migration.
- **Platform resource boundaries** (#42): Linux 4.7+ uses `RLIMIT_DATA`, while Windows uses a Job Object to constrain worker memory. Production workers use a 512 MiB hard limit and a 384 MiB Go soft limit. macOS does not yet have a verified hard boundary for Go mmap allocations, so custom quota scripts fail closed instead of running without isolation.

### Fixed
- **POST bodies survive same-origin 307/308 redirects** (#40): Redirected requests resend the encoded body and restore script headers and the form `Content-Type`.
- **Qianwen Token Plan utilization conversion** (#37): Fields such as `per5HourPercentage` and `per1WeekPercentage` are treated as `0..1` used ratios and multiplied by 100, fixing used-versus-remaining misclassification.
- **More tolerant AI output handling** (#37): Models may wrap scripts in explanatory text; the system prompt now makes clear that extractor input is an already-parsed JSON object and must not be passed to `JSON.parse`, with stronger Percentage-field and DevTools-request guidance.
- **Fresh frontend assets after upgrades** (#37): Entry HTML now uses `no-cache`, while content-hashed assets use an immutable long-term cache, preventing browsers from keeping an old bundle after a Docker rebuild.
- **Claude Code 2.1.220 probe compatibility** (#42): `GET/HEAD /api/hello` receives a local success response, and `GET /v1/environment_providers` returns `{"environments":[]}`, removing connectivity and cloud-environment 404/error noise. Related write endpoints remain disabled.

### Security
- **OOM and crash isolation** (#40, #42): Regex preflight still rejects common huge Arrays, infinite loops, and oversized string literals. Even if a dynamic expression bypasses preflight, it can only exhaust or terminate a constrained worker and no longer shares the MCC parent process's Go heap.
- **Bounded, fail-closed worker protocol** (#42): stdin uses a length-bounded framed protocol, with stdout/stderr capped at 4 MiB/64 KiB. Resource-limit initialization failures, malformed protocol messages, oversized output, timeouts, and context cancellation all reject execution or terminate the subprocess. Worker stderr and protocol errors never enter admin API responses.
- **Configured secrets remain in the parent process** (#42): Workers receive the original script with placeholders such as `{{apiKey}}`, not actual placeholder values; extractor workers additionally receive only the bounded upstream response body. Configured secrets are substituted only into the Go request configuration in the parent and never enter a goja runtime. Secrets hard-coded into script text still enter the worker, so placeholders should always be used.
- **Defense-in-depth SSRF protection for LLM endpoints** (#37, #42): Target hosts are checked both during configuration preflight and at dial time, blocking built-in cloud-metadata IPs and DNS rebinding; the LLM HTTP client disables redirects. Trusted loopback/private LLM proxies remain available to administrators.
- **PostCSS source map path-traversal fix**: The frontend lockfile upgrades PostCSS from `8.5.16` to `8.5.25`, fixing GHSA-r28c-9q8g-f849, where a malicious `sourceMappingURL` could disclose arbitrary `.map` files. `npm audit` now reports 0 vulnerabilities.

### Upgrade Notes
- This release does not change the custom-script contract or persistence format. Existing scripts continue to work as-is on supported Linux/Windows environments; see the macOS limitation above.
- Linux deployments should use kernel 4.7 or newer and keep the container/host `ulimit -d` at or above 512 MiB. A lower effective limit may prevent workers from processing responses near the supported 2 MiB maximum.
- Administrators should still review AI-generated scripts before saving, especially request URLs, headers, Cookie/Token placeholders, and extractor used-versus-remaining semantics.
