## v0.18.1 更新内容

### Fixed
- **Frame 写门覆盖 CC 2.1.220 多文件发布端点**：CC 2.1.220 新增 `POST /api/frame/deploy/prepare`（预检：发 slug + 文件 SHA，查缺失）与 `POST /api/frame/upload`（上传缺失文件内容）两条多文件 frame 发布端点。此前 mcc 对这两条无显式 case，落 `frame.go` default 分支返回误导性 405 `method_not_allowed` + `Allow: GET, DELETE`——对 POST 端点语义错误（端点本就是 POST，mcc 只是不实现写门），文案会原样进客户端给用户看的错误详情。现并入 `deploy/init`|`deploy/direct` 同族的 **403 `write_gate_disabled`** 分支：语义正确、与同族一致、客户端兜底文案（`multi-file publish is not available here yet (server or proxy rejected it: …)`）的错误详情更清晰；用户最终所见不变（仍走「not available」优雅降级）。2.1.211 vs 2.1.220 路径字面量 diff 审查确认：**无新增未拦截泄露端点**（仅这 2 条新增、均在 `/api/frame/` 前缀族内，fail-closed 兜底始终生效）。

### Docs
- **拦截接口清单升级为活文档**：`sdd-docs/research/2026-07-15-intercepted-endpoints.md` 新增「版本兼容性设计」节——阐明 mcc 面向未来 CC 版本（fail-closed 兜底 + 12 个前缀族匹配 + 客户端自身优雅降级三层机制，新版本默认安全、多数默认可用）；新增「复审新 CC 版本的方法」节（路径字面量 diff 方法论：Python 抽取 + `LC_ALL=C comm` 双向 diff + 分类判断，可复用）；附「何时需要为新版本显式改 mcc」判断标准表。新版本发布后只需复审 diff 出的少数端点，无需全量重审。

## v0.18.1 Release Notes

### Fixed
- **Frame write-gate covers CC 2.1.220 multi-file publish endpoints**: CC 2.1.220 adds `POST /api/frame/deploy/prepare` (preflight: send slug + file SHAs, learn what's missing) and `POST /api/frame/upload` (upload missing file contents) for multi-file frame publishing. mcc previously had no explicit case for these; they fell through `frame.go`'s default branch, returning a misleading 405 `method_not_allowed` + `Allow: GET, DELETE` — semantically wrong for POST endpoints (they ARE POST; mcc simply doesn't implement the write gate), with the text leaking verbatim into the client's user-visible error detail. They are now folded into the same 403 `write_gate_disabled` branch as `deploy/init`|`deploy/direct`: semantically correct, consistent with the family, and the client's fallback text (`multi-file publish is not available here yet (server or proxy rejected it: …)`) gets a clearer error detail; the user-visible outcome is unchanged (still gracefully degrades to "not available"). A 2.1.211 vs 2.1.220 path-literal diff audit confirmed **no new unintercepted leaked endpoints** (only these 2 new ones, both under the `/api/frame/` prefix family; the fail-closed fallback always holds).

### Docs
- **Intercepted-endpoints catalog upgraded to a living doc**: `sdd-docs/research/2026-07-15-intercepted-endpoints.md` gains a "version-compatibility design" section — explaining that mcc is forward-compatible with future CC versions (three layers: fail-closed fallback + 12 prefix-family matches + the client's own graceful degradation; new versions are safe by default and mostly work by default); a "how to re-audit a new CC version" section (a path-literal diff methodology: Python extraction + `LC_ALL=C comm` two-way diff + classification, reusable); and a decision table for "when you need to explicitly change mcc for a new version". After a new release, you only re-audit the few endpoints the diff surfaces — no full re-audit needed.
